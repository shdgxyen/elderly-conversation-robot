# 开发路线图

| 阶段 | 当前范围 | 状态 |
|---|---|---|
| Phase 0 | 仓库、配置、文档、协议、状态枚举 | 本次实现 |
| Phase 1 | FastAPI、SQLite、MockLLM、文本对话持久化 | 本次实现 |
| Phase 2 | ESP-IDF 状态屏骨架、JSON Lines、心跳、按键 | 本次实现 |
| Phase 3 | 真实串口联调和按钮触发的完整 mock 对话 | 下一步 |
| Phase 4 | 本地人脸检测、注册与访客模式 | 未开始 |
| Phase 5 | 真实 STT / LLM / TTS 和网络错误治理 | 未开始 |
| Phase 6 | 1.43C 板载音频与播放链路 | 未开始 |
| Phase 7 | 长期记忆、事实确认与自传草稿 | 未开始 |

下一次迭代应先在真实 USB 串口上完成 Phase 3，并加入协议握手、重连和端到端测试。Phase 2 的 STOP 事件只更新设备状态；Phase 3 还需给 LLM/TTS/播放任务增加取消令牌、播放完成事件和幂等请求 ID，避免停止后又进入 `SPEAKING` 或客户端重试产生重复轮次。随后再选择摄像头和音频传输方案。
